# Japan Atlas v3 — deployment and editing

## View locally, no account
Open `index.html` in a modern browser. All five routes remain. The manual editor under each activity saves changes to this browser or, once GitHub is configured, commits them without calling OpenAI; **Export edits** downloads the entire updated HTML. No AI service or payment is necessary for manual editing.

## Free hosting with automatic commits (GitHub Pages)
1. Back up your existing `index.html`. If you already have a public GitHub repository for the atlas, replace its `index.html` and add **both** `.github/workflows/atlas.yml` and `scripts/edit_atlas.py` at exactly those paths. GitHub's web uploader may omit hidden folders; create the workflow file via Add file → Create new file, entering the full path. Or clone your repository and copy the full folder (including `.github`). Commit to `main`.
2. Settings → Pages → Build and deployment → Source → **GitHub Actions**. In Settings → Actions → General, ensure Actions are allowed. In a repository with branch protection, allow the workflow's token to write to main or adapt this workflow to use a review branch. This workflow commits only `index.html` and publishes it. All edits and public repo content are publicly visible. Do not enter sensitive details, flight booking codes, or passwords into an edit request.
3. Actions → Atlas edit and publish → Run workflow (leave request empty) for first deployment if needed. Open the URL from Pages settings. Free public GitHub Pages hosting is subject to GitHub's policies and limits; no guarantee of permanent free service.
4. To use AI, obtain an OpenAI API key separately at https://platform.openai.com/api-keys. Set a project spending limit/budget as available. In the repository go to Settings → Secrets and variables → Actions → New repository secret. Name it `OPENAI_API_KEY`; paste the key there, not in the HTML. Optional repository variable `OPENAI_MODEL` overrides `gpt-4.1-mini`.
5. Create a **fine-grained** GitHub personal access token (https://github.com/settings/personal-access-tokens/new), choose only your atlas repository, set an expiration and Repository permissions → Actions: Read and write. Do not give it access to other repositories. In the deployed atlas, open Settings / AI, enter `owner/repository`, branch `main`, and the token. The token is held in memory only; re-enter after page reload. The repo slug is saved locally. Use a trusted browser/device, revoke the token if compromised. This is an owner-only editing capability, not anonymous editing for family viewers.
6. Click **Ask AI / edit this stop** below any activity. Enter a request and explicitly approve sending it. The workflow calls the OpenAI API, validates the JSON text fields, commits the actual HTML, and deploys that commit via GitHub Actions. The page links to the workflow status; reload after the run succeeds. A failed run makes no AI edit. The workflow uses existing context, not live web research; new information should be verified. Only a selected activity's text fields are changed, not other stops or its group of alternatives. AI API usage is separately billed; a ChatGPT Plus subscription does not include API credits. GitHub Actions usage is subject to limits. Do not use secrets in prompts.
7. To make an immediate non-AI edit, expand Manual edit and save; Export edits then replace `index.html` in GitHub to publish. Local edits remain on that browser and override the same activity until cleared. To publish all manual changes, export first and upload the exported file.

## Actual venue photos and Google ratings
The file includes a small set of sourced exact-location photos and free exact-landmark Wikipedia references, and avoids generic food images. More photos can be loaded automatically from Google Maps Places when enabled. In your Google Cloud project enable Maps JavaScript API and Places API (New), enable billing, create a **browser API key** with website restrictions (your exact GitHub Pages domain/path) and API restrictions (Maps JavaScript and Places). Configure quotas and budget alerts. In site Settings enter this restricted browser key. The site performs lazy lookups when cards enter view, using name matching and showing the matched Google listing/address; check matches especially for chains. Swipe or use arrows; contributor attribution is displayed. This may incur Google API fees. The key is stored locally, not exported. Google images and ratings are not embedded in the saved data, and no Google data is persisted to GitHub. Google data is subject to https://developers.google.com/maps/documentation/javascript/policies; photos may not exist for every venue. The independently sourced static photos can be blocked by their hosts; fallback photo links remain. Tabelog ratings are not available via this Google integration and only sourced snapshots are shown; missing numbers are not invented. Alternative prices and hours are planning ranges, not all individually verified. Directions open walking or transit in Google Maps; approximate hotel walking times are not measured routes.

## Notes
- Central Tokyo stays are Asakusa only. Some options exceed $150 total/night in New Year. Expedia search offers are property-level, not confirmed exact room inventory. No bookings were made.
- Manual editing is supported without API access; AI commits, live Maps photos, and actual GitHub deployment require the setup above. A public static site cannot safely contain a private OpenAI key or automatically write to GitHub without authorization.
- The site uses no build process. Mobile and desktop layout is responsive; full live API/deployment testing requires your own credentials.

## V4: Refresh Expedia hotel quotes (free, no Expedia API credentials)
Every hotel stay now has **Search current Expedia listings** and **Refresh / update quotes**, both in the timeline and Hotels tab. The search opens Expedia with the actual check-in/check-out, one room, and four adults (two on the final night). Tokyo searches are centered on Asakusa; inspect walking distances and private bathroom details before selecting an offer.

1. Click the refresh button. Open the current Expedia results. Enter the total in USD for the entire stay (not per night), or mark a property as no offer returned / not checked. Existing unedited quotes remain unchanged.
2. Alternatively, click **Copy ChatGPT refresh request**, paste it into ChatGPT with Expedia connected, and paste the resulting JSON array into the refresh dialog. Review the data before applying. New hotels are accepted only when the import explicitly records a private bathroom; Tokyo candidates also need Asakusa and walking times of 15 minutes or less to Senso-ji and transit. These are user-reported checks, not automatic verification.
3. **Apply locally** saves the revised prices on the device and updates the hotel sorting/budget immediately. **Commit quotes & publish** sends the reviewed quotes to the same GitHub Actions workflow used for itinerary edits, without calling OpenAI. Reload after deployment succeeds. To publish locally applied quotes, use Export updated HTML and replace index.html, or submit the reviewed quotes via the refresh dialog. Clear local refresh to revert browser-only changes.
4. Update **all** files from the V4 ZIP, including the new `scripts/refresh_hotels.py` and revised `scripts/edit_atlas.py`. No additional GitHub secret is necessary for reviewed quote updates. Existing OpenAI key stays in `OPENAI_API_KEY` and is used only by AI activity edits.

This does not automatically fetch Expedia inventory into the page. Expedia's Travel Redirect API requires partner-issued credentials and its developer site currently reports new applications are paused (https://developers.expediagroup.com/travel-redirect-api). The ChatGPT Expedia connector is not a public endpoint callable by the standalone website. Do not use your Expedia login password as an API credential. Original quote dates and newly reviewed quote dates are shown; availability and exact room/onsen category still require confirmation on Expedia. No bookings are made.
